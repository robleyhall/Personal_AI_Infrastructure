# SECURITY_REVIEW — Personal AI Infrastructure Corporate Bundle

**Document purpose:** Standalone artifact for corporate Information Security review. Describes what the corporate bundle does, what it does not do, and why it should be acceptable on a corporate-managed macOS laptop.

**Scope:** Tier 3 corporate bundle only (8 green + 4 yellow skills, bash tools, slim sidecar, instruction block). Voice server, TypeScript skill tools, and excluded skills are explicitly out of scope; see `EXCLUDES.txt`.

**Audience:** Information Security reviewers, compliance, IT policy owners.

---

## 1. What it is in one paragraph

The corporate bundle installs a set of plain-text Markdown instruction files, a handful of bash scripts, and a slim bash wrapper under `~/.pai/` (or a user-chosen alternate directory). Together they give GitHub Copilot CLI an ambient "assistant memory" — a persistent record of how the user works, lessons they've learned, and their role framing — that survives across Copilot CLI sessions. Nothing in the bundle fetches external resources, installs packages, runs daemons, or exposes network ports. It is, structurally, a dotfiles project: instructions + scripts + markdown.

## 2. Threat model

### What the bundle *can* do

- Read files the user has already authorized Copilot CLI to read
- Write markdown summaries, JSONL ratings, and learning notes to files inside `~/.pai/` (or the directory specified by `PAI_USER_DIR`)
- Execute bash scripts that invoke `python3`, `date`, `grep`, `sed`, `wc`, `find`, `rsync` — all OS-provided
- Prepend instruction text to each Copilot CLI session via the shared `copilot-instructions.md` file, influencing how the AI behaves

### What the bundle *cannot* do

- Install software from any package manager (no npm, pip, brew, bun, apt)
- Open network connections (no inbound or outbound sockets in any script in Tier 3)
- Run as a daemon, cron job, or launchd service
- Bypass Copilot CLI's built-in file-access policies
- Read files the Copilot CLI itself cannot read
- Execute arbitrary binaries — there are no compiled binaries in the bundle
- Silently upgrade itself — upgrades require the user to rerun the installer against a new bundle version

### Attack surface

The single new entry point introduced by the bundle is the `pai` shell alias, which points at `~/.pai/sidecar/pai-copilot-corp`. That script is ~60 lines of reviewable bash that:

1. Sets three environment variables (`PAI_DIR`, `PAI_USER_DIR`, `PAI_SESSION_ID`)
2. Runs `~/.pai/tools/learning-readback.sh` once to materialize `startup-digest.md` (a Markdown summary of recent learnings, written to `~/.pai/MEMORY/LEARNING/startup-digest.md`)
3. Executes `copilot` with whatever arguments the user passed
4. On exit, appends a log line to `~/.pai/logs/sidecar.log` and cleans up `~/.pai/state/` stale files

The user can always bypass the sidecar by invoking `copilot` directly.

## 3. Network footprint

**Zero new network endpoints introduced by this bundle.**

All bash scripts are filesystem-only. The sidecar does not touch the network. The voice server and its corresponding curl calls are intentionally excluded from this bundle (see `EXCLUDES.txt`).

Skills that *can* cause external fetches via Copilot CLI's built-in `web_fetch` / `web_search` tools:
- **Research** — gated by a user-maintained allowlist at `~/.pai/USER/research-allowlist.txt`
- **ContentAnalysis/ExtractWisdom** — inherits Research's constraints when fetching

Every such fetch goes through Copilot CLI's existing network path, which is already subject to corporate proxy / SSL-inspection / egress controls. The bundle does not introduce a second network path.

## 4. Filesystem footprint

**Default install location:** `~/.pai/`

**Approximate size:** 5–10 MB (markdown + bash). The bulk is Fabric prompt patterns (~30 markdown files) and skill workflow descriptions.

**Runtime writes (all under `~/.pai/` unless relocated):**

- `~/.pai/MEMORY/LEARNING/**/*.md` — task and system learning files, written when the user explicitly ends an ALGORITHM phase or runs `capture-work-learning.sh`
- `~/.pai/MEMORY/LEARNING/startup-digest.md` — regenerated by `learning-readback.sh` at each session start
- `~/.pai/MEMORY/LEARNING/SIGNALS/ratings.jsonl` — one line per explicit user rating
- `~/.pai/MEMORY/WORK/active.md` — current task status (single file, overwritten)
- `~/.pai/MEMORY/RELATIONSHIP/YYYY-MM-DD.md` — user-stated durable facts (best-effort)
- `~/.pai/logs/sidecar.log` — session start/end log lines
- `~/.pai/state/*` — ephemeral state files

**Never written by the bundle:**

- Anywhere outside `~/.pai/` (or `$PAI_USER_DIR` if set)
- Any file in `~/.ssh`, `~/.aws`, `~/Library/Keychains/`, `~/Library/Containers/com.microsoft.*`, `~/Library/Group Containers/`, or any path the instruction block's §12 Security Rules enumerate

**Data classification consideration:**

Learning files accumulate content derived from the user's work. If the user works on corporate material, those learning files inherit the corporate data classification. The installer documents this explicitly in the README. The files stay local on the laptop and are covered by corporate DLP on any managed Mac.

## 5. Process footprint

- **No daemons.** The corporate bundle does not start the voice server or any other persistent process.
- **No cron / launchd jobs.** The installer does not create any scheduled tasks.
- **No background processes spawned at install.** Everything runs synchronously during user-invoked commands.
- **Sidecar lifecycle:** `pai-copilot-corp` runs for exactly one Copilot CLI session and exits when Copilot CLI exits.

## 6. Dependencies and supply chain

**Runtime dependencies (OS-provided; no installs during bundle setup):**

- bash
- python3
- rsync
- date, grep, sed, find, wc, head, tail

**Not used in Tier 3:**

- bun
- node / npm
- pip
- brew
- any other package manager

**Supply chain:**

The only external supply-chain element is the upstream PAI repository on GitHub (MIT-licensed, author Daniel Miessler). Skills and tools are copied from the upstream repo at install time via `rsync`. Upgrades are manual: the user fetches a new version of the upstream repo and reruns `install-corporate.sh`. There is no auto-update path.

## 7. Secrets / credentials

- The bundle **does not store, transmit, or request any credentials**.
- No API keys are used in Tier 3 (skills that require API keys — PAIUpgrade — are excluded).
- The §12 Security Rules instruction block *explicitly prohibits* the AI from reading `~/.ssh/*`, `~/.aws/*`, any file named `*secret*`, `*credential*`, `*token*`, `*key*` in dotfile or config directories.
- The bundle does not modify existing credential stores.

## 8. Telemetry

**None.** The bundle does not phone home, does not report usage, and does not collect analytics. Every file written is local, and every log line is local and user-readable.

## 9. Uninstall

```bash
rm -rf ~/.pai/
```

Also remove:
- The `pai` alias from the user's shell rc (one line)
- The PAI instruction block from `~/.copilot/copilot-instructions.md` (delimited by markers `[BEGIN PAI BLOCK]` / `[END PAI BLOCK]`)

No residual state; no daemons to kill; no caches to purge.

## 10. Relationship to existing corporate Copilot setup

The bundle is **additive** to an existing `~/.copilot/copilot-instructions.md`. It does not remove or rewrite corporate-mandated instruction content. The PAI block is inserted between explicit start/end markers that corporate reviewers can verify programmatically:

```
[corp-mandated preamble — unchanged, must remain first]
...
[BEGIN PAI BLOCK]
...PAI ambient rules...
[END PAI BLOCK]
...
[corp-mandated post-content, if any — unchanged]
```

Instruction precedence: earlier content generally takes precedence in LLM instruction following, so corp-mandated rules remain authoritative.

## 11. Known limitations Info Sec should be aware of

1. **Learning files are not encrypted at rest.** They rely on standard macOS FileVault + corp disk-encryption posture. This matches the treatment of other developer artifacts in `$HOME`.
2. **Instruction compliance is probabilistic, not deterministic.** The §12 Security Rules are AI instructions, not hooks. If the AI disobeys, the sidecar and bash scripts do not stop it. Mitigation: Copilot CLI's built-in file-access controls still apply at the tool layer.
3. **Accidental commit of learning files to corporate repos.** A developer could `git add ~/.pai/MEMORY/` if they had linked it into a repo (unusual). Mitigation: README warns against; `.gitignore` template provided.
4. **The `pai` alias is a convenience.** Users can bypass it by invoking `copilot` directly. That is a feature, not a flaw — it gives users an escape hatch if the sidecar misbehaves.
